# Project Prompt: Smart Health — AI-Driven Health Center & Supply Chain Management

## 1. Project Overview

Build a fully functional, responsive, multilingual AI-powered healthcare management platform for Primary Health Centres (PHCs) and Community Health Centres (CHCs). The platform should help district administrators and healthcare staff monitor medicine stock, patient footfall, bed availability, doctor attendance, and diagnostic test availability in real time.

The main goal is to reduce medicine shortages, improve resource allocation, increase healthcare transparency, and help administrators make data-driven decisions.

## 2. Technology Stack

### Frontend

* React.js with Vite
* TypeScript
* Tailwind CSS for responsive styling
* shadcn/ui for modern UI components
* React Router for navigation
* Recharts for analytics and graphs
* Axios for API requests
* React Hook Form and Zod for form validation
* Lucide React for icons

### Backend

* Node.js and Express.js
* REST API architecture
* JWT authentication with role-based access control
* bcrypt for password hashing
* Socket.IO for real-time dashboard updates
* Node.js validation and centralized error handling

### Database

* MongoDB with Mongoose for flexible healthcare data management
* Store users, health centres, medicine inventory, patient visits, beds, doctor attendance, diagnostic tests, alerts, and audit logs.

### AI and Analytics

* Python with FastAPI for AI/ML microservices
* Pandas and scikit-learn for demand forecasting and resource utilization analysis
* Integrate a suitable LLM API for multilingual natural-language queries and report summaries
* Use configurable rule-based alerts as a reliable fallback when AI services are unavailable.

## 3. User Roles

Implement secure dashboards for:

1. **District Administrator:** View all PHCs/CHCs, compare performance, receive critical alerts, and approve resource transfers.
2. **Health Centre Manager:** Manage local inventory, staff attendance, beds, diagnostic tests, and patient statistics.
3. **Doctor/Healthcare Staff:** View duty schedules, update attendance, check bed availability, and access assigned operational information.
4. **Inventory Manager:** Record medicine receipts and usage, manage batches and expiry dates, and request replenishment.

Each role must have different permissions and accessible routes.

## 4. Core Features

### A. District Dashboard

* Display total health centres, patient visits, available beds, medicine stock-outs, and doctor attendance.
* Show critical, warning, and normal status indicators.
* Display a district map with PHC/CHC markers.
* Filter by district, centre, date, and facility type.
* Show charts for patient trends, inventory levels, and centre performance.
* Provide a recent activity and alerts panel.

### B. Medicine Inventory Management

* Add, update, and remove medicine records with appropriate permissions.
* Track medicine name, batch number, quantity, minimum stock level, expiry date, and supplier.
* Record incoming stock and medicine consumption.
* Generate early stock-out alerts based on consumption rates and lead times.
* Identify near-expiry medicines.
* Maintain complete stock movement history.

### C. AI-Based Demand Forecasting

* Predict future medicine demand using historical consumption and patient footfall.
* Display predicted demand for the next 7, 30, and 90 days.
* Recommend reorder quantities and estimated replenishment dates.
* Show forecast confidence or limitations.
* Allow staff to review and approve recommendations before any stock transfer or order.

### D. Patient Footfall Analytics

* Record daily patient visits by centre and department.
* Show daily, weekly, and monthly patient trends.
* Identify peak hours and unusually high demand.
* Forecast expected patient load.
* Recommend staffing adjustments based on predicted workload.

Use aggregated or synthetic patient data for analytics and avoid exposing personal patient information.

### E. Bed Availability

* Track total, occupied, available, and out-of-service beds.
* Categorize beds by type.
* Update occupancy in real time.
* Generate high-occupancy alerts.
* Display facility-level bed availability.

### F. Doctor Attendance

* Manage staff profiles, schedules, and duty rosters.
* Record check-in/check-out timestamps.
* Calculate attendance percentages and scheduled-versus-present status.
* Flag missing attendance records and potential staffing shortages.
* Do not assume absence merely because an attendance record has not been entered.

### G. Diagnostic Test Management

* Track available tests, equipment status, required consumables, and daily capacity.
* Record test availability and service interruptions.
* Alert managers when tests become unavailable.
* Display which centres can currently provide particular tests.

### H. Smart Resource Redistribution

* Compare stock levels, demand, bed occupancy, and diagnostic capacity across centres.
* Recommend transferring surplus medicines or resources to centres facing shortages.
* Consider expiry dates, transport time, compatibility, and minimum reserve levels.
* Show the reason behind each recommendation.
* Require authorized human approval before executing transfers.

### I. Multilingual AI Assistant

* Support English and Hindi, with architecture ready for additional Indian languages.
* Allow users to ask questions such as:

  * "Which centres may run out of essential medicines this week?"
  * "Show PHCs with high patient footfall and low doctor attendance."
  * "Which centres have available beds?"
  * "Recommend medicine redistribution between nearby centres."
* Return concise answers grounded in authorized application data.
* Include source data, relevant dates, and uncertainty where appropriate.
* Enforce role-based permissions for every query.

### J. Alerts and Reports

* Create configurable critical, warning, and informational alerts.
* Support in-app notifications and optional email notifications.
* Generate downloadable CSV reports and printable PDF summaries.
* Provide daily, weekly, and monthly operational reports.
* Track alert acknowledgment and resolution status.

## 6. Backend API Requirements

Create REST endpoints organized into modules:

* `/api/auth` — login, logout, current user, token refresh
* `/api/users` — user and role management
* `/api/centres` — centre listing and details
* `/api/inventory` — medicine stock and stock movements
* `/api/patients` — aggregated patient visit records
* `/api/beds` — bed status and occupancy
* `/api/attendance` — schedules and attendance
* `/api/tests` — diagnostic test availability
* `/api/forecasts` — demand predictions
* `/api/recommendations` — resource redistribution suggestions
* `/api/alerts` — alerts and resolution
* `/api/reports` — report generation and exports
* `/api/assistant` — multilingual AI queries
* `/api/audit-logs` — authorized audit history

Implement pagination, filtering, sorting, input validation, consistent API responses, rate limiting, secure CORS configuration, and centralized error handling.

* StaffMember
* AttendanceRecord

* ResourceRecommendation

Include timestamps, relationships or references, indexes, validation, and facility-specific access controls.

## 8. Security and Reliability

* Hash passwords with bcrypt or Argon2.
* Implement secure authentication and role-based authorization.
* Validate and sanitize all inputs.
* Protect sensitive endpoints against unauthorized access.
* Use environment variables for secrets.
* Never commit API keys or database credentials.
* Keep audit logs for important changes.
* Use synthetic data for the demo.
* Handle network failures, unavailable AI services, and database errors gracefully.
* Do not present forecasts as guaranteed outcomes or allow AI to make autonomous clinical decisions.
* Follow applicable Indian healthcare privacy requirements, including the DPDP Act where applicable.
